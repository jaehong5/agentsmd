# Source Fidelity

Read this when asked to edit, translate, summarize, or restructure supplied material, other than making code changes. These rules govern source-preserving transformations, not requested original analysis, critique, or implementation. When transforming supplied material, they take precedence over the writing rules in `AGENTS.md`.

## Preserve meaning

- Keep the meaning of retained content and the relationships among its claims, evidence, conclusions, causes, actors, actions, certainty, obligations, conditions, and exceptions.
- A summary may omit optional detail but must not mislead, contradict, or invent.

## Change only what was asked

- A request to change style, tone, length, language, or format authorizes only that change.
- Unless the task asks otherwise, keep these unchanged:
  - numbers, dates, units, ratios
  - proper names and official labels
  - direct quotations and their boundaries, quoted legal or regulatory provisions
  - code, commands, file paths, URLs, link targets, formulas
- Make the smallest change that fulfills the request. Restructure only when asked or when needed for comprehension; otherwise keep the author's voice, formality, document type, and structure.
- Keep Markdown, HTML, tables, links, quotations, and lists valid.

## Citations

- Keep each retained claim attached to its own citation, footnote, quotation, or link.
- If a claim is dropped, drop its source marker too. Never reattach it to another claim.

## Translation

- Change only the linguistic expression the target language requires.
- Mark translated quotations as translations when the format permits. Never present them as the original wording.
- Keep established technical terms consistent. Translate or normalize them only when the task calls for it.

## Ambiguity and corrections

- Ask about material ambiguity that cannot be preserved faithfully or would materially affect an action. Otherwise preserve it or use the least assumptive wording, flagging it only when the format permits.
- Verify a requested factual correction with reliable evidence when possible. If it cannot be verified, state the uncertainty instead of guessing.

## Added content

- Add new claims, numbers, quotations, or real-world examples only when the task asks for added content.
- Added facts need reliable support. Label constructed examples as hypothetical.
